# Юзербот: клонирование чатов Telegram

Бот работает от имени вашего аккаунта и копирует сообщения в «клоны», то есть в отдельные приватные каналы:

- **Лички.** Все входящие личные сообщения попадают в один канал **Private Messages**. При запуске бот ищет его по названию, а если не находит, создаёт. В каждом сообщении есть шапка: от кого, ID и тип (текст, фото, видео, документ, голосовое, кружок, стикер, GIF, альбом). Альбомы приходят альбомами.
- **Группы.** Только те, что вы добавили командой `.clone add ID`. Для каждой создаётся свой канал **Clone: [название]**, в шапке: от кого, ID, группа и ID группы. Автосоздание клонов выключено (`AUTO_CREATE_CLONES=false`).
- **Команды.** Пишете их сами в любом чате (`.get`, `.clone`, `.ex` и другие, см. ниже), сообщение с командой сразу удаляется.

## Почему он не падает

Прошлая версия «умирала» молча. Здесь каждая типичная причина закрыта отдельно:

| Что случается | Что делает бот |
|---|---|
| Пропал интернет, Telegram разорвал соединение | Telethon переподключается сам. Если связи нет дольше 5 минут или Telegram перестал отвечать на проверки, бот пересоздаёт клиента с нарастающей паузой (5 с, 10 с, … до 5 минут) и пробует бесконечно. |
| Сообщения пришли, пока бот был офлайн | После переподключения и при каждом запуске бот догружает пропущенное из всех личек и добавленных групп, а также из новых личек с непрочитанными. Дубли отсекаются по базе. |
| Обновления «тихо» перестали приходить при живом соединении | Каждые 5 минут бот проверяет связь, а каждые 30 минут дополнительно сверяет чаты с историей. |
| FloodWait (Telegram просит подождать) | Бот ждёт ровно столько, сколько попросили, и продолжает. Сообщение из очереди не теряется. |
| Процесс убили или сервер перезагрузился | Очередь и соответствие «чат → клон» лежат в SQLite (`data/state.db`), после запуска бот продолжает с того же места. Сам процесс поднимает systemd или Docker. |
| Клон удалили вручную | Бот создаёт новый клон (для личек сначала ищет канал с тем же названием) и пересылает в него. |
| В чате запрещена пересылка | Бот скачивает медиа и загружает его заново (до 200 МБ), текст и шапка сохраняются. |
| Сообщение не удаётся переслать по иной причине | 5 попыток с паузами, потом сообщение записывается в список ошибок (`python -m userbot status`), а очередь идёт дальше. |
| Ошибка в одном сообщении | Ловится и логируется, приём остальных не останавливается. |
| Сессию отозвали (вышли из аккаунта в настройках Telegram) | Бот пишет понятную ошибку и выходит с кодом 3. Systemd в этом случае не перезапускает его впустую, нужен повторный вход. |

## 1. Получите api_id и api_hash

1. Откройте https://my.telegram.org и войдите по номеру телефона (код придёт в Telegram).
2. Выберите **API development tools**.
3. Заполните форму: App title и Short name любые (например, `myclone`), Platform: Desktop. URL можно оставить пустым.
4. Нажмите **Create application** и скопируйте **App api_id** и **App api_hash**.

Никому не показывайте эти ключи и файл сессии `data/*.session`: с ними можно управлять вашим аккаунтом.

## 2. Настройте

```bash
cp .env.example .env
nano .env        # впишите API_ID и API_HASH
```

Главные настройки в `.env` (все с комментариями в `.env.example`):

- `FORWARD_PRIVATE` и `PRIVATE_CLONE_TITLE` — копировать ли лички и как называется их канал (по умолчанию `Private Messages`).
- `FORWARD_BOTS` — копировать ли лички от ботов (по умолчанию нет).
- `INCLUDE_OUTGOING` — копировать ли ваши собственные сообщения (по умолчанию нет, только полученные).
- `EXCLUDE_CHATS` — исключить чаты (id или `@username` через запятую).
- `AUTO_CREATE_CLONES` — `true` вернёт старое поведение, когда клон создаётся для каждой группы сам.
- `CMD_REPLY` — куда приходят ответы команд: `saved` (в «Избранное», по умолчанию, чтобы в общих чатах никто их не видел) или `here` (в тот же чат).

Чат 777000 (служебные уведомления Telegram) исключён всегда. Если переслать код входа в другой чат, Telegram его аннулирует, и вы не сможете войти на новом устройстве.

## Команды

Команду пишете сами в любом чате, сообщение с ней сразу удаляется. Ответ приходит в «Избранное» (или в тот же чат при `CMD_REPLY=here`), а `.get` кладёт найденные сообщения в чат, где вы написали команду.

| Команда | Что делает |
|---|---|
| `.get <ссылка>` | Получить сообщение по ссылке (в текущий чат) |
| `.get reply` | Получить сообщение, на которое вы ответили |
| `.get last N [ссылка]` | Последние N сообщений из чата или темы |
| `.get lastI N [ссылка]` | Последние N фотографий |
| `.get search "текст" [ссылка]` | Поиск по тексту |
| `.getM [N] <ссылка>` | Все медиа: видео, фото, GIF и файлы. Ссылка на сообщение — из него или его альбома, на чат или тему — из всего чата (до 500, `GETM_LIMIT`) |
| `.getMU [N] <ссылка на сообщение>` | Все медиа автора этого сообщения в том же чате (можно и ответом на сообщение: `.getMU`) |
| `.getMU [N] <ссылка на чат> @user` | Все медиа этого пользователя в чате (вместо `@user` можно ID) |
| `.unread [N]` | Непрочитанное из чатов, где включены уведомления (до N из каждого, по умолчанию 20). В самих чатах сообщения остаются непрочитанными |
| `.unread list` | Только список таких чатов и сколько в них непрочитанного |
| `.ex @user` | В чёрный список (можно ID или ответом на сообщение) |
| `.rm @user` | Из чёрного списка |
| `.list` | Показать чёрный список |
| `.aaa` | Узнать ID текущего чата |
| `.clone add ID` | Создать клон группы (без ID — текущей) |
| `.clone remove ID` | Перестать клонировать группу (сам канал-клон остаётся) |
| `.clone list` | Список всех клонов |
| `.group on/off` | Вкл/выкл пересылку из групп |
| `.status` | Статус бота |
| `.commands` | Список команд |

Без ссылки `.get last`, `.get lastI`, `.get search` и `.getM` работают в текущем чате. N не больше 100 (`GET_LIMIT`), поиск показывает до 20 результатов (`SEARCH_LIMIT`).

Ссылки, которые понимает `.get`:

```
https://t.me/username/123              сообщение
https://t.me/c/1234567890/123          сообщение в приватном чате
https://t.me/username/424/1142         сообщение 1142 в теме 424
https://t.me/c/1234567890/424/1142     то же в приватном чате
https://t.me/username/1142?thread=456  тема в параметре
tg://resolve?domain=username&post=123
t.me/username/123                      без https://
```

Чтобы добавить группу: напишите в ней `.aaa`, ID придёт в «Избранное», затем там же `.clone add -100…`. Или просто напишите `.clone add` прямо в группе.

## Переход со старой версии

Все настройки и состояние лежат в той же базе `data/state.db`, `clones.json` не нужен. При первом запуске новой версии клоны, которые старая версия создала автоматически (каналы `📥 …`), отключаются: бот в них больше не пишет, но сами каналы остаются, их можно удалить вручную. Нужные группы добавьте заново через `.clone add`. Старые настройки `CHAT_TYPES`, `ONLY_CHATS` и `CLONE_PREFIX` больше не используются, их можно удалить из `.env`.

## 3. Запуск через Docker (рекомендуется)

Нужны Docker и Docker Compose.

```bash
# первый вход: спросит номер телефона, код и пароль 2FA, если он есть
docker compose run --rm userbot python -m userbot login

# запуск в фоне
docker compose up -d --build

# логи
docker compose logs -f

# состояние: клоны, чёрный список, очередь, ошибки
docker compose exec userbot python -m userbot status
```

`restart: unless-stopped` поднимает контейнер после падения и перезагрузки сервера. Вход нужен один раз: сессия сохраняется в `./data`.

## 4. Запуск через systemd (без Docker)

Нужен Python 3.10 или новее.

```bash
sudo useradd -r -m -d /opt/userbot userbot
sudo cp -r . /opt/userbot && sudo chown -R userbot: /opt/userbot
cd /opt/userbot
sudo -u userbot python3 -m venv venv
sudo -u userbot venv/bin/pip install -r requirements.txt

# первый вход
sudo -u userbot venv/bin/python -m userbot login

# служба
sudo cp deploy/userbot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now userbot

journalctl -u userbot -f                              # логи
sudo -u userbot venv/bin/python -m userbot status     # состояние
```

Служба перезапускается всегда, кроме кода выхода 3 (слетела сессия). В этом случае выполните `login` заново и `sudo systemctl restart userbot`.

## Просто попробовать на своём компьютере

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # впишите ключи
python -m userbot login
python -m userbot
```

## Где что лежит

```
data/userbot.session   сессия Telegram (секрет!)
data/state.db          клоны, настройки, чёрный список, очередь, история
data/userbot.log       лог (ротация, 3 файла по 5 МБ)
userbot/app.py         основной цикл, сторож соединения, догрузка
userbot/cloner.py      клоны и копирование сообщений с шапкой
userbot/commands.py    команды .get, .clone, .ex и другие
userbot/links.py       разбор ссылок t.me для .get
userbot/storage.py     база SQLite
tests/                 тесты: python -m unittest discover tests
```

## Ограничения

- Клонируются только новые сообщения, начиная с первого запуска. Старая история не переносится.
- Правки и удаления в исходном чате в клон не попадают.
- Подпись к медиа ограничена 1024 символами, поэтому длинный текст под фото приходит отдельным сообщением сразу после него. Для стикеров и кружков шапка идёт отдельным сообщением, а медиа отвечает на неё.
- После долгого простоя пропущенное догружается по 500 сообщений на чат за проход (`CATCHUP_LIMIT`), остальное подтянет следующая проверка. Порядок сообщений в клоне после разрыва может немного перемешаться.
- Новые лички, пришедшие во время простоя, догружаются по непрочитанным в 50 последних диалогах.
- Юзерботы не запрещены, но массовое создание каналов Telegram может ограничивать. Если упрётесь в лимит, бот сообщит об этом в логе и не будет падать.
